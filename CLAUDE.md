# Claude Code Configuration

Personal website. Only non-discoverable conventions and operational gotchas live here — everything else (stack, scripts, structure) is readable from `package.json` and the code.

## Non-obvious conventions

- Working files (notes, scratch tests, one-off markdown) never go in the repo root — use `tests/`, `docs/`, or `scripts/`.
- Blog post images: `public/images/posts/<post-slug>/`, referenced as `/images/posts/<slug>/<file>` in MDX (CI fails on missing or case-mismatched refs — S3 is case-sensitive, macOS isn't). App/project images: `app/images/<Project>/` via `getImageUrl()`. OG share cards: `public/images/og/`, generated by `scripts/generate-og-image.py`.
- 3D models: `public/images/models/*.glb`, loaded client-side only via `TrophyModel.tsx` (`@google/model-viewer` must never reach an SSR chunk). Unlike the rest of `/images/*`, this path is synced to the CDN with a 1-hour (non-immutable) TTL so a model can be replaced in place.
- Pizza-map data: `public/images/pizza/*.json`, generated by `scripts/generate-pizza-data.py` from a SQLite scrape of Google Places that is **kept outside the repo** (`--db <path>`; the scrape cost ~$183 in API calls and is not reproducible for free — don't discard the DB). Fetched root-relative by `PizzaScoringMap.tsx`, so the CDN must stay same-origin: the bucket sends no CORS headers. Synced with a 1-hour TTL like `models/`, since a regeneration replaces the files in place. The Pizza Score is a *percentile* (`5 × (1 − Φ(z))` over locally smoothed ratings), not a star rating — the spread it's stretched across is under half a star.
- New blog post: add `posts/<slug>.mdx`, run `python3 scripts/generate-og-image.py`, commit the new card in `public/images/og/`. The CI `og-cards` job fails the build otherwise. Everything else (homepage list, sitemap, RSS, prev/next nav) is automatic.
- New project route: must be added manually in three places — `app/routes.ts`, `STATIC_PATHS` in `app/routes/sitemap[.]xml.ts`, and `staticLinks` + `CATEGORY_BY_KEY` in `app/routes/_index.tsx`.
- Typography: `font-neo` (Inter) for body text, `font-mono` (JetBrains Mono) for code — not Tailwind's default `font-sans`. Detailed component patterns: `docs/code-standards.md`.

## Deployment

Full architecture, versioning, and CloudFront notes: `docs/deployment.md`. Read it before changing the build, the deploy workflow, or anything under `server/`.

Two rules that bite without warning, so they live here rather than behind the link:

- **Anything an SSR-rendered module imports must be in `server/package.json` or in `ssr.noExternal` (`vite.config.ts`).** The SSR build externalizes all npm deps; the Lambda installs a separate hand-maintained list. Get it wrong and those routes 500 **for bots and curl only** — browsers recover client-side, so a browser test will tell you it's fine when it isn't. After a build that touched imports, run the `verify-lambda-deps` skill.
- **Commits must be Conventional Commits.** A Husky `commit-msg` hook runs commitlint and rejects anything else, and the type decides the release: `fix:` → patch, `feat:` → minor, `feat!:` → major; `chore:`/`docs:`/`refactor:`/`ci:`/`test:`/`perf:` don't release. Pushing to `master` deploys.
