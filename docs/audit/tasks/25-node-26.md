# 25 — Move to Node 26 when Lambda supports it

|            |                                         |
| ---------- | --------------------------------------- |
| Finding    | Raised after the audit                  |
| Needs      | Repo change; a deploy to test           |
| Risk       | Medium                                  |
| Size       | 2 hours                                 |
| Depends on | **Two external conditions, below.** Do not start until both hold. |

## Preconditions

1. **`nodejs26.x` is generally available on AWS Lambda**, not in preview. As of 12 November 2026 it was a public preview, which AWS says is not covered by its SLA or support and should not run production workloads. Check `https://docs.aws.amazon.com/lambda/latest/dg/lambda-runtimes.html`.
2. **Architect accepts `runtime nodejs26.x`.** Check the release notes of `@architect/architect` and its `@architect/inventory` / `lambda-runtimes` dependency for the version that adds it, and update to it if needed.

If either is not true, record the date you checked in the status table and stop. There is no pressure: Node 24 is supported until about April 2028.

## Steps

One PR, changing all of these together:

| File | Change |
| --- | --- |
| `app.arc` | `runtime nodejs24.x` → `runtime nodejs26.x` |
| `package.json` | `--target=node24` → `--target=node26` in `build:arc:server`; `engines.node` → `>=26.0.0` |
| `.nvmrc` | `24` → `26` |
| `.github/workflows/deploy.yml` | every `node-version: 24` → `26` |
| `package.json` devDependencies | `@types/node` to `^26` |
| `.github/dependabot.yml` | remove the `@types/node` ignore rule, or keep it so it follows the runtime again at the next upgrade |
| `docs/deployment.md` | any mention of Node 24 |

Check that `esbuild`'s installed version knows the `node26` target (`npx esbuild --version`, then try the build).

## Verify

- `npm ci` on Node 26, then `npm run lint && npm run typecheck && npm run format:check && npm test && npm run build:arc && npm run check:lambda-deps`.
- The Lambda's Node runtime bundles the AWS SDK v3, which the Camel Up Cup email relies on (`@aws-sdk/client-sns` is imported at runtime, not shipped). After deploying, submit a test bot and confirm the email arrives (task 02's verification).
- Server-side Stockfish runs as WebAssembly inside the Lambda: do the Collaborative Checkmate disagreement test from task 24.
- `/healthcheck`, a blog post and a chess page return 200 to a bot user agent.

Deploy this on its own so it can be reverted on its own. Commit as `chore: …` if you want no release, or `perf: …` to cut one.

## Done when

`aws lambda get-function-configuration … --query Runtime` shows `nodejs26.x` and the three checks pass.
